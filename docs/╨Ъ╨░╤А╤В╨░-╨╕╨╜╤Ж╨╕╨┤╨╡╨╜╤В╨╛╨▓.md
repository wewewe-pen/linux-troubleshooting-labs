# Карта пройденных инцидентов

Здесь собраны все сценарии из исходных лабораторных записей. Самые показательные вынесены в отдельные incident reports в каталогах репозитория.

## Networking

1. Неверный `/32` route к `1.1.1.1`: Longest Prefix Match, gateway vs destination, ARP FAILED.
2. Firewall сломал локальный DNS: loopback, `tcpdump` на правильном interface, INPUT policy drop.
3. `/etc/hosts` подменил настоящий DNS: разница `getent` и `dig`, NSS order.
4. Service слушал только loopback: `127.0.0.1` vs `0.0.0.0`, binding vs firewall.
5. Ложный след с INPUT 80/443 для исходящего `curl`: client/server direction, OUTPUT и established traffic.

## Processes

6. Неправильный CWD процесса: relative path + CWD.
7. Persistent zombie: parent не выполнял reap child.
8. False positive: `PPID=1`, `TTY=?`, отсутствие в `jobs` сами по себе не ошибка.
9. Stale PID file: PID file не доказывает существование process.

## systemd

10. Service не запускается из-за неправильного `WorkingDirectory`.
11. `After=` без `Requires=`: ordering не равен dependency.
12. Service active, но disabled: runtime state не равен boot activation.
13. После `SIGTERM` появляется новый PID: `Restart=always`, kill process не равен stop service.
14. Нужно остановить и запретить activation: `stop` + `mask`, разница `disable` и `mask`.
15. Service active, endpoint недоступен: неверный port + firewall loopback.
16. Dependency не запускается: `Requires=` должен находиться в `[Unit]`.
17. Crash loop и StartLimit: application error, restart policy, rate limit, `reset-failed`.
18. Vendor unit и drop-in override: effective configuration собирается из нескольких источников.

## Permissions

19. Individual users вместо общей application group: перейти к role/group model.
20. Слишком открытая parent directory: конечные file permissions не защищают весь tree.
21. Разные роли на одной directory: owner `rwx`, group `--x`.
22. Объект, который нельзя трогать: troubleshooting включает решение «ничего не менять».
23. Корень application tree: group access + отдельный ACL для auditor.
24. `public/index.html`: правильных file permissions недостаточно без traversal parent directory.
25. `config/app.conf`: read-only файл и traverse directories — разные требования.
26. `config/secret.key`: секрет `root:root 600`, без лишнего shared access.
27. `deploy.sh`: реальное выполнение важнее одной проверки execute bit.
28. `runtime/`: web создаёт/удаляет, dev только traverse.
29. `collab/`: SGID для наследования общей group.
30. `collab/`: Default ACL нужен для совместной записи при `umask 027`.
31. `collab/`: sticky bit защищает deletion/rename, но не content modification.
32. `reports/report.txt`: named ACL для read-only доступа auditor без общей group.
33. `incoming/`: SGID + Access ACL + Default ACL решают три разные задачи.
34. `untouched/`: уже правильный объект не надо «чинить».
